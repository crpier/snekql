### Held versions

- **PyMySQL 1.2.0**, although 1.2.3 is available. aiomysql remains 0.3.2, its latest
  published release. The [upstream compatibility fix](https://github.com/aio-libs/aiomysql/pull/1081)
  is still open. Newer PyMySQL breaks binary parameter encoding, including BLOB
  writes and migration checksums. Keep both existing `<1.2.1` bounds; revisit
  after a compatible driver release and native/fresh-artifact tests. The current
  GitHub advisory query for 1.2.0 returned no published matches, not a security
  guarantee. See [driver compatibility](../mariadb-support.md#python-driver-compatibility).
- **pydantic-core 2.46.5**, although 2.49.0 is available. Pydantic 2.13.5 explicitly
  requires `pydantic-core==2.46.5`. Pydantic is already the latest stable release.
  Do not override that exact requirement. Revisit with a Pydantic release that
  selects a newer core.

After the changes, `uv lock --upgrade --dry-run` proposes no further changes.
The installed-package outdated list contains only these two held packages.

[0.11](https://github.com/astral-sh/uv/releases/tag/0.11.0), and

prerelease resolution, script-relative project discovery, and archive/hash
validation. No custom indexes or certificate overrides needed migration.

the maintainer's global uv was not replaced.

**3.50.4**. The existing CI version assertions remain. The unpinned `3.14`
installation steps can select a newer patch with new uv; their actual platform
behavior must be checked by CI rather than inferred from this local run.

pathspec 1.1.1, pluggy 1.6.0, tomlkit 0.15.1, and trove-classifiers
