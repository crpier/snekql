01 / Executive verdict

Move to ty, but do not stop at the PR prototype

The migration is viable. The best declaration under ty 0.0.75 is shorter than both main and PR 242, and it keeps the owner checks that motivated the explicit-owner prototype.

Recommended declaration:

class User[S = Pending](Model[S, "User[Fetched]"]):
    id: GenCol[int] = Integer(
        primary_key=True,
        default=PENDING_GENERATION,
    )
    email: Col[str] = Text()
    nickname: Col[str | None] = Text(default=None)


class Order[S = Pending](Model[S, "Order[Fetched]"]):
    user_id: FKCol[User, int] = ForeignKey(User.id)

The owner comes from descriptor class access. User.email becomes a column owned by User[Pending]; instance access still selects the pending or fetched value overload.

03 / Model declarations

Infer the owner at descriptor access

PR 242 proves that lifecycle-wide descriptor owners work. ty can go one step further: the descriptor can acquire its concrete query owner when Python's descriptor protocol receives the owning class.

PR 242

class User[S = Pending](
    Model[S, "User[Fetched]"]
):
    id: GenCol[User, int] = Integer(...)
    email: Col[User, str] = Text()

Recommended

class User[S = Pending](
    Model[S, "User[Fetched]"]
):
    id: GenCol[int] = Integer(...)
    email: Col[str] = Text()

Mechanism

class _UnboundOwner:
    """Descriptor has not been accessed through a model class."""


@overload
def __get__[AccessOwner](
    self,
    instance: None,
    owner: type[AccessOwner],
) -> Attr[
    WriteOwner,
    ReadOwner,
    AccessOwner,
    WriteValue,
    ReadValue,
    SetValue,
]: ...


type Col[T] = Attr[
    Table[Pending],
    Table[Fetched],
    _UnboundOwner,       # rebound to AccessOwner on class access
    T,
    T,
]

This is not the rejected inherited Self alias. The alias stores a private nominal marker that is not a Table. Class access supplies the concrete owner through owner: type[AccessOwner], a standard descriptor input that ty solves as the class being accessed. Because _UnboundOwner cannot satisfy query-owner bounds, callers cannot assign an accessed Order column back to Col[str] and launder it into a User query.

Constructor return types are part of the boundary

The marker must appear in every storage-constructor overload, including omitted-default and broad fallback arms. Leaving those returns owned by Any lets a raw Text() descriptor satisfy any model-specific update, index, or projection before class access occurs. 

@overload
def Text[T](..., default: T) -> Attr[
    Any, Any, _UnboundOwner, T, T, object
]: ...

@overload
def Text(...) -> Attr[
    Any, Any, _UnboundOwner, Any, Any, Any
]: ...

Implementation notes

  • Remove owner parameters from the four public column aliases.
  • Change the class-access overload on Attr and mirror it on FKAttr.
  • Add a matching override on JsonAttr, otherwise class access widens away MariaDB JSON methods.
  • Return _UnboundOwner from every SQLite and MariaDB storage-factory overload. Never return an Any owner.
  • Keep runtime descriptor identity unchanged. Class access still returns the same object.
  • Teach runtime logical-type extraction the one-argument aliases. This is simpler than the current last-argument convention.
  • Delete the proposed runtime owner-mismatch check. With no owner in the declaration, that mismatch cannot be written.
  • In Attr.__set_name__, reject a descriptor already bound to another owner or name. Reusing one descriptor object mutates its runtime owner and name even though the nominal marker blocks the static laundering path.

Any is not a safe placeholder for the descriptor owner. The first probe passed ordinary class access but allowed assignments and helper functions to erase an accessed column's owner. The final _UnboundOwner probe rejects all tested alias and raw- constructor laundering paths. Hiding Attr and FKAttr from backend exports still reduces access to the low-level six- and seven-parameter forms.

Remove nullability repetition

nullable=False is already redundant because the default is NOT NULL. The workspace contains 459 explicit false flags. Documentation should stop teaching them immediately.

A more useful follow-up derives effective nullability from Col[T | None]. Keep the constructor's tri-state flag during migration as an optional assertion, not a second source of truth. Resolve each annotation independently before DDL. The current whole-class hint resolution can let one unresolved sibling make every nullability check silently skip.

04 / Lifecycle model

The awkward base argument earns its place

No experiment found a shorter declaration that retains one nominal model class, generated-value narrowing, exact fetched results, and insert inference. 

class User[S = Pending](Model[S, "User[Fetched]"]):
    ...

Python typing has no higher-kinded operation that turns an inferred User[Pending] into User[Fetched]. The second model parameter is the explicit witness for that transformation. The owner/read structural methods then pass it through select, insert, joins, and returning writes.

AlternativeResultVerdict
Self as read typeResolves to User[Pending]Reject
Table[Fetched]Changes state but erases UserReject
Per-model __read_type__Works, but replaces one argument with a longer cast-backed methodReject
Fetched companion subclassWorks with materializer and inheritance changesWorse
Literal lifecycle stateSame repetition with less meaningful namesReject

Keep Pending, Fetched, PEP 696's default state, and the explicit fetched witness. Spend complexity where it removes repetition from every field, not where it saves one class-base fragment.

05 / Query inference

Carry the result once

ty cannot map arbitrary projected columns to a tuple of decoded values. It can, however, let each built query carry its row type through one nominal base. An isolated prototype reduced repeated runtime overloads this way; it was not integrated into the full package.

Nominal query shape

class _QueryShape[ScopeT, RefT, RowT]:
    def _pin_scope(self, scope: ScopeT) -> ScopeT: ...
    def _reference_type(self) -> RefT: ...
    def _row_type(self) -> RowT: ...


async def fetch_all[ScopeT, RowT](
    self,
    query: _QueryShape[ScopeT, ScopeT, RowT],
    *,
    validate: bool = True,
) -> list[RowT]: ...

In the focused probe, the invariant scope witness and covariant reference witness preserved the tested dual-union check. The probe rejected a query whose references escaped its join scope. A private nominal base also avoided the structural hole where an unrelated class satisfies a public result protocol and looks executable even though runtime rejects it.

fetch_one, 4 overloads1 generic shapeExact single row

Treat this section as evidence for a follow-up, not as a ready patch. The prototype checked representative model, scalar, tuple, join, and write results. It did not replace every query state in snekql or run the full consumer-negative matrix against an integrated implementation.

One-field select overload

The current code uses four singleton overloads for columns, aggregates, scalar subqueries, and dialect expressions. ty 0.0.75 binds one owner and value variable through a union, so one overload retains exact inference: 

@overload
def select[OwnerT: Table[Any], ValueT](
    field: Attr[Any, Any, OwnerT, Any, ValueT]
    | Aggregate[OwnerT, ValueT]
    | Scalar[OwnerT, ValueT]
    | DialectSelectable[OwnerT, ValueT],
    /,
) -> SelectValueQuery[OwnerT, OwnerT, ValueT]: ...

Arbitrary-width projections remain unavailable

Runtime accepts more than three fields, but static overloads stop at three. A real four-field call produces no-matching-overload. TypeVarTuple can preserve and append packs, which is why arbitrary-depth model joins already work. It cannot map Field[Owner, T] over a pack to recover each T.

Recommendation: generate finite overloads to a documented width, perhaps 8 or 10, for both select and returning. Keep one implementation. Do not change the pleasant variadic call syntax for a theoretical abstraction that Python typing cannot express.

Public query annotations

Consumers should not need twenty concrete query-state class names. If naming built queries remains a supported use case, expose small result-oriented types such as Select[RowT] and Write[ResultT]. Keep builder-state classes private. This makes query annotations describe what execution returns rather than how the implementation reached that state.

06 / Correctness findings

Fix these while the interface is moving

The wide audit found type claims that disagree with runtime behavior. These matter more than reducing internal generic syntax.

1

Mutation returning claims Pending, runtime creates Fetched

High

await tx.execute(update(User).returning()) and delete's equivalent infer list[User[Pending]]. The materializer calls decode_model_row, which explicitly writes _snekql_state = "Fetched". The incorrect type even lets a returned row pass back into insert statically.

Reuse the model class owner/read witness in update and delete. Carry ReadT to whole-row returning, or put list[ReadT] on the returning result marker. The focused prototype infers list[User[Fetched]] with ty 0.0.75.

2

Scalar comparison erases value compatibility

High

An integer column accepts a scalar string subquery in all six *_col methods because the parameter includes Scalar[Any, Any]. There is no runtime type gate; the database decides how to coerce it.

A strict Scalar[Any, ValueT | None] check rejects useful integer-versus-AVG comparisons. The viable design separates scalar projection result from comparison domain, for example Scalar[OwnerT, ResultT, CompareT]. A contravariant comparison witness accepted integer and AVG cases and rejected strings in the validation probe.

3

Nullable foreign keys reject their real target

High

FKCol[User, int | None] makes references() demand a target column of int | None. A normal User.id: int is then rejected. Overloads specialized on nullable and non-null self types can preserve the underlying key type and reject a string target.

4

Projection left joins return None without saying so

High

This is already documented as a caveat. A projected NOT NULL column from the nullable side remains typed as str, while materialization returns None for an unmatched row. The current query generic stores value types without per-slot owner relationships, and Python has no mapped variadic operation to fix only the right-side slots.

Reject projection left_join for now, or require an explicit wrapper that widens selected values to optional. Model left joins are already sound and should remain the default advice.

5

Class field specifiers miss required constructor arguments

High

ty's detailed dataclass_transform field behavior currently targets function specifiers. With snekql's classes whose work lives in __new__, wrong values and unknown keywords are diagnosed, but User() can omit a required email. This is a lost static guarantee and must appear in the consumer conformance suite.

The validated fix is to expose storage declarations as registered overloaded functions. Call syntax stays Text(...) and Integer(...); runtime already treats the current classes as factories returning Attr objects. The function probe rejected missing required fields, positional construction, unknown keywords, wrong values, and incompatible defaults.

6

Joins can certify an unrelated condition

Low runtime risk

Covariant model-owner inference lets both model and projection joins widen the requested model independently of the owners in on=. ty accepts an Order join whose condition relates Team and Region. The projection variant then puts Team and Region in static scope while omitting Order. Runtime rejects it immediately.

A simple tighter union is not enough because ty widens the new owner to a union. A tested static fix needs an invariant model-owner witness and separate structural views for new-owner-on- left and new-owner-on-right. Ship it only if that private machinery remains local; the runtime check already prevents bad SQL.

7

One unresolved annotation can disable sibling checks

Medium

Hint resolution currently evaluates the whole model. One unresolved sibling makes nullability resolution return unknown, and validation silently skips affected columns. A probe accepted Col[int | None] = Integer(), emitted NOT NULL DDL, and then rejected None at construction.

Evaluate annotations independently with Python 3.14's forward-ref support. If nullability remains unknowable, require an explicit flag or fail before DDL. Also reject optional primary-key annotations; MariaDB forces primary keys non-null regardless of the read type.

07 / Public interface

Stop exporting implementation vocabulary

SQLite exports 92 names and MariaDB 99. Much of that is not useful to a caller writing models or queries.

Remove or replace

  • ModelMeta is implementation, not a caller-facing type.
  • Attr and FKAttr expose six and seven generic parameters. A read-only ColumnRef[OwnerT, T] is enough for public annotations.
  • Table is mostly an internal generic bound.
  • Concrete query-state classes should give way to result-oriented query types.
  • Duplicate namespace and inherited column aliases should collapse to one documented spelling.

No non-test, non-example project code imports Attr, FKAttr, ModelMeta, or Table. PR 242 is already a breaking prototype, so this is the right time to narrow the interface before those names acquire external users.

10 / Recommended sequence

Implement in slices that can fail independently

  1. Freeze the consumer contract. Add positive and rule-specific negative ty probes for required constructor fields, lifecycle access, owners, defaults, nullable FKs, joins, returning writes, and result shapes. Pin ty==0.0.75.
  2. Restore constructor requiredness. Convert pure __new__ storage factories to registered overloaded function field specifiers, preserving the validated default matrix. Remove the broad Any fallback.
  3. Rebind descriptor owners. Start with a failing owner-free declaration probe, add _UnboundOwner to aliases and every constructor return, change Attr.__get__, mirror FK and JSON subtype behavior, add the __set_name__ reuse guard, then mechanically migrate declarations.
  4. Fix lifecycle and value soundness. Correct mutation returning, nullable FK targets, scalar comparison domains, and the projection-left-join contract before describing the migration as preserving guarantees.
  5. Deepen query result types. Introduce private nominal query/result bases and replace repeated transaction overloads. Keep the invariant scope witness and negative unjoined-reference probes.
  6. Simplify low-risk overloads. Merge singleton select arms into one union overload. Generate finite projection and returning overloads to a documented maximum.
  7. Narrow the public interface. Remove metaclass and multi-parameter descriptor implementation types from backend exports. Replace concrete query-state annotation names with result-oriented types if callers still need named queries.
  8. Make annotations authoritative. Resolve per-field hints, derive nullability where possible, reject optional primary keys, and stop teaching redundant nullable=False.
  9. Finish the checker migration. Add tool.ty rules, convert suppressions, update docs/examples, remove Pyright and Pyrefly, and run an installed-wheel consumer probe before merging.

The smallest high-value production change is owner rebinding plus the three correctness fixes around mutation lifecycle, required fields, and nullable foreign keys. The nominal query base and public export cleanup can follow without changing model syntax again.
